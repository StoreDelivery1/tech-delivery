================================================================================
EVIDENCE 3: AIOGRAM DISPATCHER BEHAVIOR
================================================================================

Aiogram Framework Rule:
  When a message is processed by a dispatcher:
    1. Dispatcher iterates through included routers in order
    2. Each router checks its handlers against the update
    3. If a handler matches, it executes
    4. Update is marked as HANDLED
    5. Dispatcher STOPS processing (no further routers checked)

In this case:
    1. Dispatcher sees "📊 Статистика"
    2. Checks start_router → no match
    3. Checks activation_router → no match
    4. Checks manager_router → MATCH FOUND ✓
       - Executes: manager.py:statistics_handler
       - Sends message
       - Mark as HANDLED
    5. Dispatcher stops (message already handled)
    6. courier_router NEVER CHECKED

ROOT CAUSE SUMMARY
================================================================================

PROBLEM: Routing Conflict

CAUSE: Multiple routers handle the same message "📊 Статистика"
  - admin_router has admin_statistics_handler
  - manager_router has statistics_handler
  - courier_router has courier_statistics_handler

ISSUE: Dispatcher processes routers in this order:
  1. start_router
  2. activation_router
  3. manager_router  ← MATCHES AND STOPS HERE
  4. courier_router  ← NEVER REACHED
  5. admin_router    ← NEVER REACHED

RESULT: manager_router intercepts ALL "📊 Статистика" messages
  - manager_router's handler executes first
  - Courier gets "❌ Користувача не знайдено" (not a manager)
  - courier_router's handler never gets called
  - Courier's TRACE logging never appears

FIX: Reorder routers or add role-based filtering to prevent manager_router
     from handling courier messages
